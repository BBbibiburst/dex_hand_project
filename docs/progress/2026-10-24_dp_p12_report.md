交叉接管后又执行固定预算40次短序列搜索（每root 8个候选，15或30控制步），包含时间对齐、最近arm构型对齐及oracle腕姿诊断。仍为0/40。最佳为root 3 Close早期、30步aligned current-orientation序列：跟随率0.461、物体上升2.14 mm、接触/对向接触均1.0，仍低于冻结阈值0.5和3 mm。没有建立Preparation数据集，没有训练分类器/控制器，也没有把这些候选送入GRU+Supervisor声称完整成功。

## 4. 冻结承载验证协议

沿用P9协议，未修改阈值：Preparation后腕部竖直上移5 mm，10步探测，再10步保持。只有同时满足以下条件才记为`PREPARATION_VALIDATED`：

- 物体实际上升 ≥ 3 mm；
- object-following ratio ≥ 0.5；
- 20步contact fraction ≥ 0.8；
- 20步拇指对向多指接触fraction ≥ 0.8。

`CONTACT_ESTABLISHED`仅表示存在接触；`PREPARATION_VALIDATED`是离线承载诊断；`FINAL_VERIFIED`仍由原Strict profile判定（尾段最小/最终抬升≥55 mm、速度/角速度、接触、grasp、桌面接触及穿透等全部原阈值）。三者没有混用。

## 6. 有界短时序候选搜索

1. 同索引专家时序 + 当前腕姿；
2. 同索引专家时序 + oracle专家腕姿（仅诊断）；
3. Close窗口内最近arm目标 + 当前腕姿；
4. 最近arm+hand联合目标 + oracle专家腕姿（仅诊断）。

每条均保存唯一ID、source root、时间对齐、动作hash、完整prepared snapshot、trace、IK失败数和承载失败指标。结果0/40 validated；所有接触实验的高接触率均没有被误记为承载正例。
